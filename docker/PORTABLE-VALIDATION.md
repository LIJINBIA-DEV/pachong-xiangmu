## 2026-10-20 fix1：Linux 页面保存硅基流动密钥

镜像标签：`mediacrawler-portable:20261020-proxy-fix1`，架构 `linux/amd64`。

旧版本只实现 Windows DPAPI，并在非 Windows 系统抛出
`image_subject_key_use_environment`。Windows 上运行 Docker 时，应用实际处于 Linux，
因此界面保存失败；旧保存测试限制在 Windows 执行，未发现此问题。

- 在旧 Linux 镜像中用临时目录和合成密钥精确复现。
- Linux 新增加密保存，主密钥与密文位于持久数据卷的隐藏目录，目录权限 0700、文件权限 0600；Windows DPAPI 保留。
- 实际 Linux 容器、断网条件下，保存、跨进程读回、并发、失败保留、损坏恢复、留空保留、清除、接口脱敏及隐藏文件保护等 34 项测试通过。
- Windows 原有图片云服务测试 8 项通过。
- 每次镜像构建增加实际 Linux 密钥保存、读回、响应遮蔽和清除检查，避免再次只检查服务能够启动。
- 错误请求的密钥输入不会在图片设置接口的验证响应中回显。

测试全部使用合成凭据，不代表真实 SiliconFlow Key 已通过鉴权；未读取或调用用户密钥。
完整 data 备份同时包含密文和主密钥，仍应妥善保管。
交付镜像旁的验收记录补充最终 HTTP、容器重建、镜像导入和文件哈希结果。
