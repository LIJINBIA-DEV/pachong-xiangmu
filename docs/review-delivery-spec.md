# 审核结果打包导出与文件列表简化规格

日期：2026-10-12  
状态：已按此规格完成本地实施；详情见[实施与验收记录](review-delivery-implementation.md)。Spark 未更新。

## Problem Statement — 问题

用户需要在人工审核后，下载能够离线使用的帖子和图片。目前“导出审核结果”只下载 Excel，虽然统计合格图片数量，但没有包含图片文件，用户无法一起拿到审核后的图片。

人工审核的采集文件列表同时显示采集主文件和同轮的语义结果文件，容易让用户把同一次采集误认为两份独立数据。配置页展示多种保存格式，也增加了当前仅使用 Excel 流程的操作成本。

## Solution — 方案

1. 人工审核的文件选择器只显示每轮采集的主 Excel，隐藏同轮的 `_semantic.xlsx`。隐藏仅影响该选择器，后台保留语义结果和证据读取能力。
2. “导出审核结果”下载一个 ZIP，包含审核结果 Excel，以及最终保留帖子中已标记合格且可正常读取的原始图片。
3. 图片按平台、帖子 ID 分目录；Excel 提供相对路径对应关系，解压后可以离线找到图片。
4. 未下载、下载失败、损坏或导出时无法读取的图片不伪装成成功导出。界面和包内说明明确报告缺失。
5. 配置页仅显示 Excel 保存格式，其他格式暂时隐藏，保留底层兼容能力。

## User Stories — 用户故事

1. 作为审核人员，我希望同一轮采集只在审核文件列表出现一个主文件，以免选错数据。
2. 作为审核人员，我希望隐藏语义结果文件后仍能查看 Jev 判定依据，以便核对文本筛选。
3. 作为审核人员，我希望一次下载获得 Excel 和合格图片，以便直接使用结果。
4. 作为审核人员，我希望只导出本帖最终结论为合格的帖子，以免混入已排除或未有结论的帖子。
5. 作为审核人员，我希望只打包保留帖中标记合格的图片，以免混入不合格或未标记图片。
6. 作为审核人员，我希望导出遵循已经保存的人工改判，以便结果与界面一致。
7. 作为审核人员，我希望同轮补采的数据按现有任务关联一起导出，以免遗漏相关轮次。
8. 作为使用结果的人，我希望图片按帖子 ID 整理，以便辨认不同帖子的图片。
9. 作为使用结果的人，我希望 Excel 中有图片相对路径对应表，以便离线查找图片。
10. 作为使用结果的人，我希望原来的九个交付字段和正文、评论保持原样，以便继续使用现有表格。
11. 作为审核人员，我希望导出明确说明待审核帖子和缺失图片数量，以便知道结果是否完整。
12. 作为审核人员，我希望没有合格帖时收到清楚提示，以免下载一个看起来成功的空包。
13. 作为审核人员，我希望导出失败能够重新尝试且不改变审核状态，以免丢失已经完成的工作。
14. 作为配置采集的人，我希望保存格式只显示 Excel，以便直接使用目前的采集与审核流程。
15. 作为已有任务的使用者，我希望隐藏其他格式不删除旧数据或破坏历史任务的读取，以免影响已有结果。
16. 作为大批量采集的使用者，我希望打包大量图片时能够看到状态、避免反复提交，以便知道下载是否仍在准备。

## Implementation Decisions — 实现决策

### 1. 范围与术语

- **采集主文件**：一次采集导出的主要 Excel，是人工审核的选择入口；不保证包含搜索返回的所有原始帖子。
- **语义结果文件**：同轮 Jev 筛选结果及证据，文件名以 `_semantic.xlsx` 结尾；不是 Qwen 图片识别结果。
- **审核结果包**：根据当前选中采集任务及其关联轮次，导出的 ZIP。
- **保留帖**：按照现有审核服务计算的最终结论为合格的帖子。继续遵循既有语义拒绝、账号排除和人工改判优先规则，不另造一套判定逻辑。
- **合格图片**：保留帖内最终图片标记为合格，并且原始本地文件可读取、下载完整且有效的图片。

### 2. 审核文件选择器

- 只显示采集主 Excel；不显示语义结果文件、内部识别缓存、审核状态或续跑检查点。
- 同轮主文件和语义结果文件通过现有任务关联识别，不只依赖界面显示的排序。
- 历史选择若指向语义结果文件且对应主文件存在，则切换至对应主文件；保留已有审核记录的关联。
- 若主文件不存在，仅剩语义结果文件，不将其冒充正常主文件；给出缺失提示，不删除后台数据。
- 数据管理页的语义文件可见性不在本次范围中，避免未经讨论扩大隐藏范围。

### 3. 导出选择与一致性

- 复用现有任务数据加载、审核状态和图片有效性检查接口。
- 导出时以已保存的审核状态为准；保存进行中或保存失败时不开始导出，提示先完成保存。
- ZIP 中仅包含保留帖及这些帖的合格图片。不合格帖的图片、未标记图片、模型证据和内部缓存不混入交付文件。
- 有未审核帖时允许导出当前已保留部分；页面和包内说明标注“部分结果”及待审核数量。
- 帖子被人工保留但没有可导出合格图片时，仍保留该帖的 Excel 记录，明确标注“无可导出合格图片”，不擅自改变帖子结论。
- 导出使用一次一致的审核快照，避免一个包的 Excel 和图片按照不同时间的标记选择；完成后不改写原数据、人工标记或模型缓存。

### 4. ZIP 内容与对应关系

- 包内包含“审核结果.xlsx”、图片目录、“导出说明.txt”。
- “审核结果”工作表继续使用现有九个字段：编号、平台、原帖链接、标题、发布时间、发布地点、命中关键词、发布内容、与关键词一相关的评论。
- 新增“图片对应表”工作表，记录审核结果编号、平台、帖子 ID、原图片名、包内相对路径和导出状态；一张图片一行，无图片的保留帖有明确状态记录。
- 路径以图片目录、平台、帖子 ID、图片文件名组织；保留原文件名，冲突时生成稳定且不覆盖已有文件的名称。
- 同帖因不同关键词组合产生多行结果时，允许多行引用同一图片；包内实际文件去重，不能把不同平台的相同帖子 ID 混为一帖。
- 图片采用已下载的原始文件，不用审核缩略图代替，不为导出重新调用 Jev 或 Qwen。
- 路径与文件名须安全且兼容 Windows、Linux；导出不能访问数据目录以外的文件。
- 正文和评论按原文保留；以等号等字符开头的采集文本继续作为文字保存，不能变成 Excel 公式。

### 5. 缺图与失败提示

- 导出说明包含选中任务、导出时间、保留帖数、实际打包图片数、待审核帖数、缺失图片和无合格图片帖的数量。
- 对合格但未能打包的图片，在图片对应表中保留原图片名和具体原因，不填写虚假的成功路径。
- 缺图时允许生成部分结果包，页面明确提示“导出完成，有图片缺失”，并指向包内说明。
- 零保留帖、无法生成 Excel 或无法完成 ZIP 时返回失败，不下载空白包、不宣称成功。
- 导出不自动补下载图片；用户是否补下载由后续功能处理。

### 6. 配置页

- 保存格式仅展示 Excel（`.xlsx`）；正常新建和保存配置提交 Excel 格式。
- 历史配置选择了其他格式时，界面说明当前配置页仅支持 Excel；用户保存配置或发起新任务时使用 Excel，不静默沿用隐藏选项。
- 不因打开配置页切换已经运行的任务；不删除旧格式文件，不移除底层读取和历史兼容逻辑。
- 保持 Excel 与文本语义筛选、图片识别等现有选项的联动，不改变采集和模型规则。

### 7. 下载与资源使用

- 复用现有审核导出入口和统一异常处理，下载类型由 Excel 改为 ZIP；按钮明确说明导出“Excel＋合格图片”。
- 打包期间展示状态，避免重复提交；失败后允许重试。
- 既有部署为 Spark 上的 Docker，交付从服务器持久化数据读取；本次不修改存储目录、Jev 中转、Qwen API 或其他服务。
- 大量图片不得把全部 ZIP 放入后端内存或浏览器 Blob 后才开始下载。实施时优先使用流式打包/下载或受控临时文件，并支持大 ZIP；具体方案属于实现选型。
- 临时文件只能清理本次导出创建的内容，不能清理采集文件、审核记录或已有图片。无需为了打包重新压缩 JPEG 等图片。

## Testing Decisions — 测试与验收

验收关注用户能看到的列表、下载包和审核结果，不针对内部函数实现方式写镜像测试。优先复用现有数据 API 和真实下载文件作为测试边界；页面测试覆盖文件选择、保存格式和下载交互。用户已确认按此方式验收：列表只显示主文件、配置只显示 Excel、解压后 Excel 能对应合格图片，且人工标记保持不变。

现有先例包括审核结果导出 API 测试、数据文件可见性与防目录越界测试、采集轮次导出测试，以及前端审核保存与配置持久化测试。

1. 同轮存在主文件和语义结果时，审核列表仅显示主文件；不同轮主文件仍各自显示。语义依据仍可读取，后台文件未被删除。
2. 旧选择为语义文件时能安全迁移至同轮主文件；缺失主文件时明确提示，不混用其他轮次。
3. 配置页仅显示 Excel；历史非 Excel 设置在新任务提交时按说明使用 Excel；旧文件仍可读取，运行中任务不被切换。
4. 通过审核导出 API 下载 ZIP，实际解压并读取 Excel、图片对应表、图片和说明，确认文件名与内容类型正确。
5. 混合保留、排除、待审核帖子，以及合格、不合格、未标记、缺失和损坏图片；逐项核对结果包内容与数量。
6. 模型建议与人工标记相反时，导出按现有最终保存结论执行；对源文件、审核记录和模型缓存做前后校验，确认没有被导出改写。
7. 核对现有九个交付字段、原文、评论筛选和 Excel 文字安全保持兼容。
8. 同帖跨关键词组合、同名图片、跨平台相同帖子 ID、同轮补采和重复图片场景中，路径对应正确，无覆盖或遗漏。
9. 缺图、无可导出图片、未审核完、零保留帖分别返回约定提示；缺图不是完整成功，失败不是空 ZIP 成功。
10. 输入目录越界、链接指向目录外文件、恶意文件名时，不允许导出服务器数据目录之外的内容。
11. 模拟导出时读取失败、客户端取消及较大图片集合；页面能重试，资源使用可控，本次临时文件可清理且原数据保留。模拟验证须标明，不作为完整大规模实际运行证据。

## Out of Scope — 不在范围内

- 修改 Jev 或 Qwen 的筛选规则、重新识别旧图片、覆盖人工修改。
- 删除语义结果文件、合并原始 Excel 或迁移电脑旧数据。
- 批量下载所有原始图片、打包已排除帖子、导出模型内部缓存或凭据。
- 自动补下载、自动续采、网盘同步、存储清理。
- 恢复其他保存格式的界面入口。
- 新增服务器服务、改变 Spark 其他服务或本次实施部署。
