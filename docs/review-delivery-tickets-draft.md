# 审核结果交付任务拆分草案

日期：2026-10-12  
依据：[审核结果打包导出与文件列表简化规格](review-delivery-spec.md)  
状态：用户通过 implement 指令授权实施；五项本地任务已发布并完成，详情见[实施与验收记录](review-delivery-implementation.md)。尚未部署。

## 拆分原则

每个任务完成后都能从用户界面操作或实际下载结果独立验收，不按前端、后端、测试分成互相无法演示的任务。现有任务关联、审核结论、图片有效性和导出入口可以继续复用，无需单列大范围重构。

01、02、03 无互相依赖，可分别实施；04 和 05 分别依赖 03，不互相阻塞。以下编号稳定，正式本地任务确认后将按依赖顺序一项一文件发布，并标记 `ready-for-agent`；存在阻塞的任务须等前置任务完成再开始。

## 01 — 人工审核只显示采集主 Excel

**What to build:** 人工审核选择器不再将同轮主文件与语义结果当作两个选择入口；语义证据和原有审核标记继续可用。

**Blocked by:** None — can start immediately.

**状态：** 草案，待确认。

- [ ] 审核选择器只展示每轮采集的主 Excel，隐藏语义结果、内部缓存和续跑检查点；不同轮主文件仍分别显示。
- [ ] 历史选择指向语义文件时，根据同轮关联转至主文件，不误用其他轮数据，已有审核记录不丢失。
- [ ] 对应主文件不存在时给出明确提示，不将仅剩的语义文件冒充主文件。
- [ ] 隐藏后仍能查看 Jev 判定依据；后台语义文件、图片和审核状态没有删除或改写。
- [ ] 数据管理页现有可见性不被顺带改变。
- [ ] 用文件列表 API 的真实数据和页面选择行为验证上述场景。

## 02 — 配置页仅提供 Excel 保存格式

**What to build:** 配置采集时只显示 Excel；历史其他格式的配置能按说明切换为新任务使用的 Excel，同时保留旧任务和旧数据兼容能力。

**Blocked by:** None — can start immediately.

**状态：** 草案，待确认。

- [ ] 保存格式界面只显示 Excel，新建和保存配置、提交新任务均使用 Excel。
- [ ] 历史非 Excel 设置明确显示当前只支持 Excel，新任务不静默提交隐藏格式。
- [ ] 打开或保存配置不改变已经运行的采集任务。
- [ ] 旧格式文件仍可读取；底层其他格式能力不被删除。
- [ ] 文本筛选、图片识别与 Excel 的现有联动不退化。
- [ ] 实际页面验证新配置、历史配置和新任务提交，并校验任务提交格式。

## 03 — 一次下载 Excel 与合格图片的 ZIP

**What to build:** 从人工审核页导出一个能够离线使用的 ZIP，包含当前任务保留帖的 Excel、可读取的合格原图、图片对应表及导出说明。

**Blocked by:** None — can start immediately.

**状态：** 草案，待确认。

- [ ] 复用现有任务加载及最终审核结论，包含关联补采轮次；仅选择保留帖和其合格图片，不包含排除帖、未标记图片或内部记录。
- [ ] 以一次已保存审核快照生成表格和图片清单；保存进行中或保存失败时不能开始导出。
- [ ] Excel 保留现有九个交付字段，正文和评论不改写，采集文字不作为公式执行。
- [ ] 新增图片对应表，审核结果编号能对应平台、帖子 ID、原图片名、包内相对路径及状态。
- [ ] 图片按平台、帖子 ID 整理，采用原始下载文件而非缩略图；包内包含导出说明及基本数量统计。
- [ ] 原始图片只从允许的数据目录读取；输入越界或指向目录外的链接被拒绝。
- [ ] 页面使用明确的 ZIP 文件名和下载类型；不将完整 ZIP 先累积在后端内存或浏览器 Blob 中。选择流式下载或受控临时文件作为基本下载方式。
- [ ] 没有保留帖时显示明确错误，不生成成功空包；基础读取异常有明确失败处理。
- [ ] 导出不调用 Jev 或 Qwen，不修改源数据、审核标记及缓存；校验导出前后内容一致。
- [ ] 从页面实际下载并解压 ZIP，读取 Excel 并逐一核对图片路径与文件内容。

## 04 — 导出完整性与复杂关联可追溯

**What to build:** 存在待审核、缺图、损坏图片或重复关联时，仍能获得明确标注的结果包，清楚知道哪些结果已导出、哪些未导出及原因。

**Blocked by:** 03 — 一次下载 Excel 与合格图片的 ZIP。

**状态：** 草案，待确认。

- [ ] 已有保留帖但审核未完成时允许导出当前部分结果；页面与包内说明同步显示待审核数量和“部分结果”。
- [ ] 合格但未能打包的图片保留对应记录和具体原因，不填虚假的成功路径；页面提示“有图片缺失”。
- [ ] 人工保留而无可导出合格图片的帖子仍在 Excel 中，并标注原因，不改变整帖结论。
- [ ] 不合格或未标记图片与“合格但打包失败”的图片区分统计，不把正常排除图片算作缺失。
- [ ] 同帖跨关键词组合时允许多行引用同一图片，包内文件去重；跨平台相同帖子 ID 不混淆。
- [ ] 同名、Unicode 或不安全文件名产生兼容且稳定的输出路径，不覆盖其他图片，ZIP 内路径无法逃出解压目录。
- [ ] 打包中途发现图片消失或无法读取时，不宣称完整成功；可生成部分包时说明缺失，无法完成归档时返回失败。
- [ ] 以混合状态、补采、重复引用、文件名冲突及导出期间读取异常的真实下载包验证对应表与统计。

## 05 — 大批量导出的状态、取消与资源管理

**What to build:** 图片较多时，用户能知道导出仍在准备或下载，避免重复提交，失败后可重试；服务器和浏览器无需容纳整包内存。

**Blocked by:** 03 — 一次下载 Excel 与合格图片的 ZIP。

**状态：** 草案，待确认。

- [ ] 页面区分准备、可下载或下载启动、失败状态，不把开始下载当作浏览器已保存完成；仅在能观测时显示真实百分比。
- [ ] 准备期间阻止重复提交，失败后允许重试；不会因此丢失或改变审核状态。
- [ ] 通过浏览器原生下载或同等无需全包 Blob 的方式获取文件，延续 03 的受控资源方案。
- [ ] 大 ZIP 支持 ZIP64；不重复压缩 JPEG 等图片，不因归档体积而线性占满进程内存。
- [ ] 临时存储不足、网络中断、客户端取消有可观测结果；只清理由本次导出创建的临时资源，不触碰原始数据。
- [ ] 验证内存和临时磁盘使用，以及重试、取消与失败路径；报告实际测试规模，不将模拟大 ZIP 测试说成完整 756 GB 实测。
- [ ] 不以此任务为理由修改 Spark 其他服务、Jev 中转、Qwen API 或部署设置。

## 整体交付验收

用户已确认的验收方式：从实际页面操作与下载 ZIP 验证审核列表仅显示主文件、配置仅显示 Excel、解压后 Excel 可对应合格图片，以及人工标记保持不变。

每个任务实施时完成自己的行为验证；全部完成后，再走一遍配置、选择主文件、核对标记、下载并解压的完整流程。发布及部署不在本次任务拆分请求的执行范围内。
